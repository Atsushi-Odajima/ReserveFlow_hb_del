# 日時・タイムゾーン規則（TIMEZONE_RULES）

## 保存方式
| データ | 型 | 意味 |
|---|---|---|
| 予約開始/終了、占有、ブロック、通知予定、監査日時 | `timestamptz`（UTC の瞬間） | 絶対時刻 |
| 営業時間・勤務時間・リソース時間 | 曜日 + 分（0〜1440）のローカル壁時計 | 事業者タイムゾーンで解釈 |
| 日付例外・開催回の日付 | `date`（事業者ローカル日付） | 事業者タイムゾーンで解釈 |
| 事業者タイムゾーン | IANA 名（例 `Asia/Tokyo`, `America/New_York`） | JST 固定はしない |

API は ISO-8601（UTC、`Z` 付き）で瞬間をやり取りし、画面表示時に **事業者タイムゾーン** へ変換する
（閲覧者の端末タイムゾーンではない。海外から予約する顧客にも店舗の時刻で表示し、タイムゾーン名を併記）。

## ローカル日付 → 瞬間
`DateTime.fromObject({year, month, day, hour, minute}, {zone: business.timezone})`（Luxon）。
- `1440` 分は翌日 00:00。
- 営業区間は瞬間の区間に変換し、隣接・重複する区間は連結する（23:00-24:00 と翌 00:00-01:00 を跨ぐ予約が可能）。

## DST（夏時間）
- **存在しないローカル時刻**（春の切替、例 America/New_York 02:00-02:59）：候補開始時刻にしない。
  営業区間の端が存在しない時刻に当たる場合は、Luxon の規則で直後の有効時刻へずらす。
- **重複するローカル時刻**（秋の切替、例 01:00-01:59 が2回）：候補開始時刻は **早い方（夏時間側）のみ**。
  同じ表示時刻が2回出る混乱を避けるため。営業区間の長さは実時間で扱う（区間自体は正しく1時間長くなる）。
- 所要時間は **実経過時間**。01:30 EST 開始 60 分は 03:30 EDT 終了と表示される。
- 対応確認済み：`America/New_York`、`Europe/London`、`Australia/Sydney`（南半球）、`Asia/Tokyo`（DST なし）。

## 最短受付時間・予約可能期間
- 最短受付：`start >= now + minNoticeMinutes`（瞬間で比較）。
- 予約可能期間：開始の **事業者ローカル日付** `<= 事業者ローカルの今日 + maxAdvanceDays`。
  例：30日なら 30 日後は可、31 日後は不可。
- 変更/キャンセル締切：`now <= start - deadlineMinutes`（瞬間で比較）。

## 通知時刻
リマインドは「開始の N 時間前」（瞬間で計算）。本文中の日時は事業者タイムゾーンで整形し、タイムゾーン名を付記。

## 日付跨ぎ・境界
- 事業者ローカル日付と UTC 日付が異なるケース（例：東京 08:00 = UTC 前日 23:00）でも、
  日付範囲の問い合わせは「ローカル日付の 00:00〜翌 00:00」を瞬間へ変換して行う。
- 「今日の予約」は事業者ローカルの今日。

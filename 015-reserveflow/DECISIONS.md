# 設計判断記録（DECISIONS）

| ID | 判断 | 理由 / 代替案 |
|---|---|---|
| D-001 | Node 22 + Fastify + PostgreSQL + React/Vite の単一リポジトリ・単一プロセス | 購入者が Render 等の1サービス＋1DBで運用できる。ワーカーもアプリ内で動くため Cron 不要 |
| D-002 | ORM を使わず `pg` のパラメータ化クエリ | ロック・排他制約・tstzrange を正確に扱うため。SQL 注入は全クエリのプレースホルダで防止 |
| D-003 | 日時は timestamptz(UTC)、営業時間は「曜日+分」のローカル壁時計、例外は date | JST 固定を避け、DST 地域でも正しく変換（TIMEZONE_RULES.md） |
| D-004 | 営業時間の優先順位：臨時休業(closed) ＞ 特別営業(special_hours) ＞ 曜日営業時間。同日に closed と special があれば closed が勝つ。ブロックはその上で差し引く | 安全側（休業を優先）。定休日でも special_hours で臨時営業できる |
| D-005 | 占有＝準備＋サービス＋片付け。スタッフ・リソースとも占有時間全体を占有。サービス時間は営業時間内、占有全体はスタッフ勤務時間・リソース時間内 | 開店前準備（勤務9:30・営業10:00）を表現でき、準備時間の重複を防ぐ。BOOKING_ENGINE.md §2 |
| D-006 | 確定時の競合防止は「事業者単位の advisory lock＋ロック内で同一エンジンによる再検証」＋「スタッフ排他制約（EXCLUDE USING gist）」の二重化 | 定員/リソース同時利用数は排他制約で表現できないためロックで直列化。スタッフの二重占有は DB が最終防衛 |
| D-007 | 冪等キー（UUID）を画面で生成し `bookings(business_id, idempotency_key)` 一意 | 連打・通信再送で同じ予約を返す（新しい管理トークンを発行し直す） |
| D-008 | 変更は「新予約作成＋旧予約を rescheduled」を1トランザクションで | 状態「変更済み」を履歴として残す。失敗時はロールバックで旧予約が残る |
| D-009 | 管理リンクのトークンは 256bit、SHA-256 ハッシュのみ保存、URL フラグメント（#t=）で渡す | サーバーログ・Referer に残らない。予約終了＋30日で失効、再発行で旧リンク失効 |
| D-010 | メール本文のリンク用トークンは送信時に発行（平文トークンを DB に保存しない）。送信失敗時はそのトークンを失効 | 秘密情報の複製を避ける |
| D-011 | 通知は plain text のみ。テンプレート変数は制御文字除去して展開 | HTML インジェクション・ヘッダインジェクションの排除 |
| D-012 | 通知の重複防止：dedupe_key 一意＋`FOR UPDATE SKIP LOCKED` で claim → sending。10 分以上 sending のものは unknown とし自動再送しない | 「二重送信しない」を優先（at-most-once）。不明分は管理画面から手動再送 |
| D-013 | 管理側手動予約は最短受付・予約可能期間・刻み・非公開を免除し、他は公開予約と同じ | 当日飛び込み・電話対応のため。二重予約は免除しない |
| D-014 | 強制予約（オーナーのみ・理由必須・監査）も重複・定員・リソース上限は免除しない | 「管理者だから二重予約可」を初期値にしない。強制でも二重予約は不可能 |
| D-015 | おまかせ割当：相乗り可能なセッション担当 ＞ 当日予約数が少ない ＞ 表示順 ＞ ID | 説明可能・決定的。AI は使わない |
| D-016 | 顧客照合：正規化した氏名＋メール一致（メールなしは氏名＋電話一致）のみ既存顧客に紐付け。それ以外は新規作成し重複候補として表示 | 他人のメールを入力された場合の誤統合を防ぐ。自動統合はしない |
| D-017 | 定員制は slots モード（同時刻相乗り）と sessions モード（開催回）の両方。開催回は生成時にスタッフ/リソースを占有 | 繰り返し開催の回を個人予約が奪わないため |
| D-018 | 繰り返しルールは週次（n週ごと）・毎月第n曜日・毎月n日に限定。ルール変更時は「未来・予約なし・個別変更なし」の回だけ作り直す | 複雑な RRULE は不要（仕様）。過去/予約済み回を勝手に変えない |
| D-019 | 待機リストは候補表示と事業者通知のみ。自動予約しない | 仕様「自動予約確定は禁止」 |
| D-020 | バックアップは事業者単位 JSON（schemaVersion/appVersion/件数/SHA-256）。復元は空の事業者へのみ、全 ID を振り直し 1 トランザクション | 上書き事故防止・同一 DB 内でも衝突しない・失敗時は無変更 |
| D-021 | CSV は UTF-8 BOM＋CRLF、先頭 = + - @ タブ CR | % は ' を前置 | Excel 互換と数式インジェクション対策 |
| D-022 | 公開予約の bot 対策：IP/事業者/メール単位のレート制限（DB 保存）、ハニーポット、送信までの最短時間 2.5 秒、任意で Cloudflare Turnstile | 初期状態では外部通信なし（プライバシー配慮） |
| D-023 | PWA は手書き SW。管理の GET（今日/ダッシュボード/カレンダー）だけ network-first でキャッシュ、書込みはキャッシュ/再送しない。オフライン時の管理予約は「下書き（未確定）」として端末保存、接続後に再検証 | 危険なオフライン同期を避ける（仕様） |
| D-024 | カレンダーのドラッグ操作は実装しない（変更は予約詳細→日時変更） | 仕様でドラッグは必須でない。誤操作防止・サーバー再検証を常に通す |
| D-025 | DST の重複時刻は早い方のみ候補、存在しない時刻は候補にしない | 同じ表示時刻が2回出る混乱の回避 |
| D-026 | 深夜0時を跨ぐ営業は「20:00-24:00」＋翌日「0:00-2:00」の2区間で登録すれば連結して扱う | 1区間で24時超を許すより入力が単純 |
| D-027 | エンジンの性能対策：占有/ブロック/予約をスタッフ・リソース単位に索引化し二分探索、Luxon 変換をメモ化 | 負荷試験で 1か月の空き枠取得 93 秒 → 0.7 秒（TEST_REPORT.md） |
| D-028 | サンプル事業者（is_sample）はメールを一切送信しない | 実顧客への誤送信防止。本番と分離 |
| D-029 | 予約管理リンク経由の変更/キャンセルは締切あり。管理側からの記録（電話で依頼された等）は締切を適用しない | 現場運用に合わせる |
| D-030 | 価格は表示用テキストのみ。決済・キャンセル料請求は実装しない | 仕様（初版対象外） |

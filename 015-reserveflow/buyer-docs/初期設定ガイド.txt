初期設定ガイド
==================================================
※パソコンで作業してください。所要時間の目安：設置30〜60分、店舗設定30分。

--------------------------------------------------
第1部 サーバーに設置する（最初の1回だけ）
--------------------------------------------------
ReserveFlow はご自身で契約したサーバー（例：Render）で動かします。以下は Render の例です。
画面の名称や料金はサービス側で変わることがあります。契約前に必ず各社の料金ページをご確認ください。

1. GitHub アカウントを作り、ReserveFlow 一式を自分のリポジトリにアップロードします。
2. Render（https://render.com）に登録し、次の2つを作成します（リージョンは Singapore 推奨）。
   ・PostgreSQL（Basic 以上。無料版は30日で削除されるため本番には使えません）
   ・Web Service（リポジトリを指定。Root Directory に「015-reserveflow」を指定）
     Build Command: npm ci && npm run build
     Start Command: npm start
3. Web Service の「Environment」に次を設定します。
     NODE_ENV = production
     DATABASE_URL = （PostgreSQL の Internal Database URL を貼り付け）
     APP_SECRET = （32文字以上のでたらめな英数字。例：パスワード生成ツールで作成）
     PUBLIC_BASE_URL = （Web Service の URL。例 https://xxxx.onrender.com）
     ALLOW_SIGNUP = true
     PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD = 1
4. デプロイが完了したら、ブラウザで  PUBLIC_BASE_URL/signup  を開き、オーナーとして登録します。
   （お名前・メールアドレス・パスワード10文字以上・店名・予約ページのURL名・タイムゾーン）
5. 登録できたら、Render の環境変数 ALLOW_SIGNUP を false に変更して再デプロイします
   （第三者が勝手に事業者登録できないようにするため）。

■ 費用の目安（2026年9月時点。変わることがあります）
  Render Web Starter 約$7 ＋ PostgreSQL Basic 約$6 ＝ 月 約$13（約2,000円）
  メール送信：Resend 無料枠（月3,000通・1日100通まで）。予約が多い場合は有料プラン（月$20〜）。

--------------------------------------------------
第2部 メール送信を設定する（おすすめ）
--------------------------------------------------
設定するまで、予約確認メール・リマインドは「記録されるだけで送信されません」。
1. メール送信サービス（例：Resend）に登録し、お店のドメイン（例 example.com）を追加します。
2. 表示される DNS 設定（SPF・DKIM、推奨 DMARC）をドメイン管理画面に登録し、認証を完了させます。
3. SMTP の情報を確認し、Render の環境変数に設定して再デプロイします。
     EMAIL_DRIVER = smtp
     SMTP_URL = smtps://ユーザー名:パスワード@smtp.サービス名:465
     EMAIL_FROM = お店の名前 <no-reply@お店のドメイン>
4. 自分宛てにテスト予約をして、確認メールが届くことを確かめます。
   届かない場合：管理画面「通知履歴」のエラー内容を確認してください。

--------------------------------------------------
第3部 お店の設定（管理画面）
--------------------------------------------------
ログイン： PUBLIC_BASE_URL/login
左メニュー（スマホは下の「メニュー」）から、上から順に設定します。

1. 事業者設定・公開
   ・事業者名、表示名、説明、電話、メール、住所、Web/SNS、ロゴ、テーマ色
   ・タイムゾーン（日本なら Asia/Tokyo）、週の始まり
   ・開始時刻の刻み（例30分）、最短受付時間（例：2時間前まで）、予約可能期間（例：60日先まで）
   ・変更締切／キャンセル締切（例：前日＝24時間前）、リマインド（例：24時間前）
   ・電話番号の入力（必須／任意／聞かない）、注意事項、予約完了メッセージ、同意文
2. 営業時間・休業日
   ・曜日ごとの受付時間（1日に複数区間も可。例 10:00〜12:00、13:00〜19:00）
   ・臨時休業・祝日休業、特別営業・短縮営業（日付指定）
3. リソース（部屋・設備）… 必要な場合のみ（スタッフとリソース.txt）
4. サービス … メニューごとに所要時間・準備時間・片付け時間・定員・必要な部屋など
5. スタッフ … 対応サービス、勤務時間、休憩。ログインさせる場合は「ログイン招待」
6. 事前質問 … 必要な場合のみ
7. 事業者設定で「予約ページを公開する」にチェックして保存
8. 表示された予約ページURLを開き、自分でテスト予約 → 管理画面で確認 → キャンセル、まで試してください。

--------------------------------------------------
第4部 毎日の使い方
--------------------------------------------------
・朝：「今日の受付」で予約と事前質問を確認
・来店時：「来店・開始」、終了時：「完了」（来なかった場合は開始時刻後に「無断欠席」）
・完了後にその場で「次回予約」
・電話やDMの予約：「新規予約・空き検索」で空きを探して登録（同じ二重予約チェックがかかります）
・休み：「休み・ブロック」に登録（既存予約は自動キャンセルされないので、警告が出たら個別に連絡）
・週1回：「CSV・バックアップ」でバックアップをダウンロードして保管
